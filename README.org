#+TITLE: ekphrasis

*ekphrasis*, /n./

*Pronunciation:* /Brit./ =/ˈɛkfrəsɪs/=, /U.S./ =/ˈɛkfrəsəs/=

*Forms:* also *ecphrasis*. Plural *ekphrases*.

*Etymology:* [< ancient Greek ἔκφρασις 'description', < ἐκφράζειν 'to describe, set forth in words', < ἐκ 'out' + φράζειν 'to point out, make known, tell'; partly through post-classical Latin /ecphrasis/.]

*1.* /Rhetoric./ A description so vivid that it seems to set its subject before the hearer's eyes. In ancient rhetorical teaching, also: one of the preliminary exercises (/progymnasmata/) in which a student practised describing persons, events, places, and times in this way.

*2.* Specifically, a description in words of a work of visual art, whether the work is real or imagined; a poem or passage of prose that takes such a work for its subject.

*3.* By extension, in criticism and art theory: any representation in one medium of what is shown in another, especially the rendering in words of something presented to the eye.

-----

Check what a user interface actually renders against a written description of what it should show.

You describe a view as Lisp data: the elements it should show, their labels, the order they sit in, and the states they can be in. ekphrasis renders a McCLIM pane headlessly and reports each element that is missing, mislabelled, out of order, in the wrong state, or too faint to see. Each finding names the check that failed, what was expected, and what was drawn, with the box it was drawn in whenever there is a drawing to locate. ekphrasis also puts each control into its highlighted state for you, and reports an outline highlight too faint against its background, or a filled highlight that hides the control's label or leaves it too faint to read.

I named the library for sense 2 with its order reversed. In sense 2 the picture comes first and the words follow it; here you write the description first, and ekphrasis reports where the rendering departs from it.

* Status

ekphrasis is at version 0.1.0. It is a library you call from a Lisp image, with no command-line interface yet. The McCLIM adapter is the only one: it renders a pane on a headless port that measures text on a fixed-width grid, so the boxes in a report are repeatable but are not the extents of a real font. Layout beyond order, relations between panes and views, and what reaches a screen are not checked yet; [[file:docs/checks.org][Checks]] ends with the full list of what ekphrasis does not check.

* Install

ekphrasis runs on SBCL (Steel Bank Common Lisp) with Quicklisp. The adapter needs upstream McCLIM, an implementation of the Common Lisp Interface Manager (CLIM), and the test suites need zebra, which is not in Quicklisp. [[file:docs/getting-started.org][Getting started]] says where each one comes from and how to make it visible to ASDF (Another System Definition Facility). With those in place, load the McCLIM adapter, which brings the core in with it:

#+begin_src lisp
(ql:quickload "ekphrasis/mcclim")
#+end_src

* A first finding

This example defines a toolbar whose pane draws a title and two controls, describes the toolbar with Reply to the left of Archive, and checks the pane against that description. The pane draws Archive first.

Define a package, a presentation type for the controls, and a frame whose =bar= pane draws the title as text and each control as an =action= presentation:

#+begin_src lisp
(defpackage #:toolbar-example
  (:use #:clim-lisp #:clim))

(in-package #:toolbar-example)

(define-presentation-type action ())

(define-application-frame toolbar ()
  ()
  (:menu-bar nil)
  (:panes
   (bar :application
        :display-function 'draw-toolbar
        :scroll-bars nil))
  (:layouts
   (default bar)))

(defun draw-toolbar (frame pane)
  (declare (ignore frame))
  (draw-text* pane "Inbox" 10 20)
  (with-output-as-presentation (pane :archive 'action)
    (draw-text* pane "Archive" 100 20))
  (with-output-as-presentation (pane :reply 'action)
    (draw-text* pane "Reply" 180 20)))
#+end_src

Write the description as Lisp data: a title reading Inbox, two =action= controls labelled Reply and Archive, and Reply to the left of Archive:

#+begin_src lisp
(defparameter *toolbar-spec*
  '(:view :bar
    :elements ((:title :kind :text :label "Inbox")
               (:reply :kind :action :label "Reply")
               (:archive :kind :action :label "Archive"))
    :order ((:left-to-right :reply :archive))))
#+end_src

Check the =bar= pane of a fresh =toolbar= frame against it, and print the report:

#+begin_src lisp
(multiple-value-bind (findings report)
    (ekphrasis/mcclim:check-frame-pane *toolbar-spec* 'toolbar 'bar)
  (declare (ignore findings))
  (write-line report)
  (values))
#+end_src

=ekphrasis/mcclim:check-frame-pane= returns three values: the findings, the report string, and the snapshot of drawn elements the findings were judged on. The report reads:

#+begin_example
bar: 1 finding (1 error, 0 warnings)
  error order left-to-right at (100 10 215 22) in bar: expected (reply archive), drawn (archive reply), displaced (archive)
#+end_example

The second line is one error from the order check, along the left-to-right axis. The box after =at= bounds both controls, as =(x1 y1 x2 y2)= in pane coordinates. The description lists Reply then Archive, the pane draws Archive then Reply, and Archive is the control displaced from the described order. With Reply drawn to the left of Archive, the same call prints =bar: no findings=.
