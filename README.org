#+TITLE: ekphrasis

*ekphrasis*, /n./

*Pronunciation:* /Brit./ =/ˈɛkfrəsɪs/=, /U.S./ =/ˈɛkfrəsəs/=

*Forms:* also *ecphrasis*. Plural *ekphrases*.

*Etymology:* [< ancient Greek ἔκφρασις 'description', < ἐκφράζειν 'to describe, set forth in words', < ἐκ 'out' + φράζειν 'to point out, make known, tell'; partly through post-classical Latin /ecphrasis/.]

*1.* /Rhetoric./ A description so vivid that it seems to set its subject before the hearer's eyes. In ancient rhetorical teaching, also: one of the preliminary exercises (/progymnasmata/) in which a student practised describing persons, events, places, and times in this way.

*2.* Specifically, a description in words of a work of visual art, whether the work is real or imagined; a poem or passage of prose that takes such a work for its subject.

*3.* By extension, in criticism and art theory: any representation in one medium of what is shown in another, especially the rendering in words of something presented to the eye.

-----

Check what a user interface actually renders against a written description of what it should show.

You describe a view as Lisp data: the elements it should show, their labels, the order they sit in, and the states they can be in. ekphrasis renders a McCLIM pane headlessly and reports each element that is missing, mislabelled, out of order, in the wrong state, or too faint to see. Each finding says where the element is drawn and why it fails. It also puts each control into its highlighted state for you, and reports a highlight too faint to see against its background, or one that paints over the control's label.

I named the library for sense 2 with its order reversed. In sense 2 the picture comes first and the words follow it; here you write the description first, and ekphrasis reports where the rendering departs from it.

* Requirements

- SBCL 2.x
- ASDF 3.x
- All deps available via =$LISP_WORKSPACE/= or Quicklisp

* Load

#+begin_src lisp
(asdf:load-system :ekphrasis)
#+end_src

* Use

Write a spec: the description of a view, as Lisp data. This one names a title and two controls, and says the controls run from left to right:

#+begin_src lisp
(defparameter *toolbar-spec*
  '(:view :bar
    :elements ((:title :kind :text :label "Inbox")
               (:reply :kind :action :label "Reply")
               (:archive :kind :action :label "Archive"))
    :order ((:left-to-right :reply :archive))))
#+end_src

Then judge a pane against it. Here =toolbar= is an application frame, and the last argument names the pane to judge: its =bar= pane draws the title as text and each control as an =action= presentation:

#+begin_src lisp
(asdf:load-system :ekphrasis/mcclim)
(ekphrasis/mcclim:check-frame-pane *toolbar-spec* 'toolbar 'bar)
#+end_src

You get back the findings, a report, and the snapshot they were judged on. When the pane draws Archive to the left of Reply, the report reads:

#+begin_example
bar: 1 finding (1 error, 0 warnings)
  error order left-to-right at (100 10 235 22) in bar: expected (reply archive), drawn (archive reply), displaced (archive)
#+end_example

* Test

Each system has its own suite:

#+begin_src lisp
(asdf:test-system :ekphrasis)          ; specs, comparison, and reports
(asdf:test-system :ekphrasis/mcclim)   ; the McCLIM adapter and its controls
#+end_src

=scripts/cold-verify.sh= runs both suites in a fresh SBCL with an empty fasl cache, fails if loading =ekphrasis= on its own brings in McCLIM, and prints =cold-verify: ok= when everything passes.

* Run

#+begin_src bash
# Foreground:
sbcl --eval '(asdf:load-system :ekphrasis)' --eval '(ekphrasis/src/main:main)'

# Build binary:
./build.sh

# Dev image (Slynk listener):
./scripts/dev-boot.sh
#+end_src
